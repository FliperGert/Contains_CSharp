### Задача 1. List

#### Текст задачи
Составить программу, которая формирует список L, включив в него по одному разу элементы, которые входят в один из списков L1 и L2, но в то же время не входят в другой из них.

#### Алгоритм решения
Метод UniqueList принимает два списка и возвращает новый список end_list. Это симметрическая разность списков, в которой каждый элемент встречается один раз.

1. Если один из списков равен null, выбрасывается ArgumentException.
2. Проходим по list1. Элемент добавляется в результат, если его нет в list2 и он ещё не был добавлен в endList (так повторы внутри одного списка попадают в результат только один раз).
3. Так же проходим по list2: элемент добавляется, если его нет в list1 и его ещё нет в endList.
4. Возвращаем endList.

Списки вводятся с клавиатуры через пробел, ввод проверяется методом InputIntList (если введено не целое число, программа просит повторить ввод). Пустой список разрешён (minCount = 0).

### Задача 2. LinkedList

#### Текст задачи
Удалить все элементы между минимальным и максимальным элементами.

#### Алгоритм решения
Метод MinMaxList работает напрямую с узлами LinkedListNode<T>, поэтому удаление во время обхода безопасно. Для сравнения элементов на тип T наложено ограничение IComparable<T>.

1. Если список равен null или пуст, выбрасывается ArgumentException.
2. За один проход по узлам находим узел с минимальным значением minNode и узел с максимальным значением maxNode. Сравнение строгое (< 0 и > 0), поэтому если одинаковых экстремумов несколько, выбирается первое вхождение.
3. Если minNode и maxNode совпадают (в списке один элемент или все элементы равны), удалять нечего и метод завершается.
4. Вторым проходом определяем, какой из двух узлов стоит левее — это начало диапазона start, а второй узел становится его концом end. Так метод корректно работает и когда максимум стоит раньше минимума.
5. Начиная с start.Next, запоминаем ссылку на следующий узел next и удаляем текущий через list.Remove(current), пока не дойдём до end. Сами минимальный и максимальный элементы остаются в списке.

### Задача 3. HashSet

#### Текст задачи
Есть перечень названий телевизионных шоу. Определить для каждого наименования шоу, какие из них нравятся всем n телезрителям, какие — некоторым из телезрителей, и какие — никому из телезрителей.

#### Алгоритм решения
Метод RatingShow получает список названий шоу и список списков любимых шоу каждого телезрителя. Все множества хранятся в HashSet<string>.

1. Если передан null или список телезрителей пуст, выбрасывается ArgumentException.
2. Из общего перечня шоу строится множество allShowSet. Множество allIntersectSet (нравятся всем) изначально копирует allShowSet, множество allAddSet (нравятся хоть кому-то) создаётся пустым.
3. Для каждого телезрителя строится множество его любимых шоу personSet, и из него отсеиваются названия, которых нет в общем перечне (IntersectWith(allShowSet)).
4. Множество зрителя объединяется с allAddSet (UnionWith) и пересекается с allIntersectSet (IntersectWith).
5. Множество «не нравятся никому» (allBedSet) получается как разность всех шоу и allAddSet (ExceptWith).
6. Три множества выводятся вспомогательным методом PrintSet. Если множество пустое, выводится строка таких нет.

Названия шоу и списки предпочтений вводятся через запятую (методом InputStringList), количество телезрителей задаётся от 1 до 10.

### Задача 4. HashSet

#### Текст задачи
Файл содержит текст на русском языке. Какие цифры встречаются в тексте?

#### Алгоритм решения
Метод DigitInText читает файл посимвольно через StreamReader.Read (в кодировке UTF-8) и добавляет каждую найденную цифру (char.IsDigit) в HashSet<char>, благодаря чему каждая цифра сохраняется один раз.

1. Если файл не существует, выбрасывается ArgumentException.
2. После чтения файла проверяется количество элементов в UniqDigit. Если цифр нет, выводится цифр нет.
3. Найденные символы копируются в List<char>, сортируются по возрастанию (digits.Sort()) и выводятся через пробел.

В меню запрашивается имя файла. Если такого файла ещё нет, он автоматически создаётся методом FillTextFile и заполняется примером текста. Перед выводом результата содержимое файла печатается на экран.

### Задача 5. Dictionary/SortedList

#### Текст задачи
Имеется список людей с указанием их фамилии, имени и даты рождения. Напишите программу, которая будет определять самого старшего человека из этого списка и выводить его фамилию и имя, а если имеется несколько самых старших людей с одинаковой датой рождения, то определять их количество.

На вход программе в первой строке подается количество людей в списке N. В каждой из последующих N строк находится информация в формате <Фамилия><Имя><Дата рождения> (ДД.ММ.ГГГГ, год от 1800 до 2100, фамилия и имя не длиннее 20 символов).

#### Алгоритм решения
Исходные данные хранятся в текстовом файле people.txt. Файл заполняется отдельным методом FillPeopleFile: он записывает в первую строку число N, а затем N строк со случайной фамилией, случайным именем и случайной датой в диапазоне 60 дней начиная с 01.01.1995 (что позволяет получать совпадения дат).

Метод OldPerson читает файл и строит коллекцию SortedList<DateTime, List<string>>, где ключ — дата рождения, а значение — список людей с этой датой.

1. Читаем первую строку и проверяем, что это положительное целое число N.
2. Для каждой из N строк проверяем: строка не равна null, в ней ровно три элемента (разделённых пробелами), фамилия и имя не длиннее 20 символов, дата соответствует формату dd.MM.yyyy (DateTime.TryParseExact) и год лежит в диапазоне от 1800 до 2100. При нарушении формата выбрасывается ArgumentException с указанием номера строки.
3. Если даты ещё нет в SortedList, добавляем её с новым списком, затем добавляем в список строку «Фамилия Имя».
4. SortedList автоматически сортирует ключи по возрастанию, поэтому самая ранняя дата (самый старший человек) находится под индексом 0 (byDate.Values[0]).
5. Если в этом списке один человек, выводим его фамилию и имя, иначе выводим количество таких людей.

### Задача 6. Перегрузка операций

#### Текст задачи
Класс Money, поля: uint rubles, byte kopeks. Метод: вычитание копеек (uint) из объекта типа Money (учесть, что денежная величина не может быть меньше 0). Результат должен быть типа Money.

#### Алгоритм решения
Класс Money хранит рубли в закрытом поле _rubles и копейки в закрытом поле _kopeks, доступ к ним организован через свойства Rubles и Kopeks. В сеттере Kopeks выполняется проверка: если переданное значение больше 99, выбрасывается ArgumentException.

В классе реализован один конструктор с параметрами по умолчанию public Money(uint rubles = 0, byte kopeks = 0). За счёт значений по умолчанию он позволяет создавать как нулевую сумму new Money(), так и сумму с заданными рублями и копейками, пропуская их через свойства.

Вспомогательные методы класса:
* AllKopeks() переводит сумму в общее количество копеек ((ulong)_rubles * 100 + _kopeks) в типе ulong для защиты от переполнения.
* FromKopeks(ulong allKopeks) выполняет обратный перевод: рубли вычисляются как allKopeks / 100, копейки — как allKopeks % 100. Если количество рублей превышает uint.MaxValue, выбрасывается OverflowException.

В актуальной версии вычитание копеек (uint) реализовано напрямую через бинарный оператор operator -(Money money, uint kopeks) (вызывается в пункте меню 7). Если вычитаемое количество копеек больше или равно текущей сумме (kopeks >= allKopeks), возвращается нулевая сумма new Money(), иначе — FromKopeks(allKopeks - kopeks). Исходный объект при этом не изменяется.

Метод ToString() возвращает строку вида В наличии N руб. и M коп.. Рубли и копейки при вводе в меню проверяются методом Check.InputInt (рубли от 0 до int.MaxValue, копейки от 0 до 99).

### Задача 7. Перегрузка операций

#### Текст задачи
К классу Money добавить операции:
* унарные: -- вычитание копейки из объекта типа Money, ++ добавление копейки к объекту типа Money;
* приведение типа: uint (явная), результат количество рублей (копейки отбрасываются); bool (неявная), результат true, если денежная сумма не равна 0;
* бинарные: - Money m, беззнаковое целое число (лево- и правосторонние операции), число обозначает копейки; - Money m1, Money m2, вычитание денежных сумм.

#### Алгоритм решения
Все операции описаны в классе Money как public static. Ни одна из них не изменяет исходные операнды: результатом всегда является новый объект Money (или значение примитивного типа), а нижняя граница в 0 копеек строго соблюдается.

1. operator ++ возвращает FromKopeks(money.AllKopeks() + 1) — копейка прибавляется к общей сумме и при достижении 100 переносится в рубли.
2. operator -- возвращает money - 1, делегируя вычитание и проверку нижней границы бинарному оператору.
